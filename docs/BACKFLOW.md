# Sokuou 回流正典

> 回流者：使用中所得之一手经验，归于 Sokuou 本仓也。
> Sokuou 之形，不由闭门构想而定，乃由众调用者之真实使用所揭示。

---

## Ⅰ · 何时回流

| 所得 | 去处 |
|---|---|
| 缺陷——数值、语义、契约、文档 | 于 Sokuou 内修复，附回归测试；不得仅在调用方打补丁 |
| 新曲线——UWP 变体、Easing 变体 | 入 Sokuou 缓动族，注明出处与依据；不得私藏于调用方 |
| 新原语——编排、延迟、错位…… | 先于调用方登记场景；第二处需要时，抽象入 Sokuou |
| 宿主通用机制——dt 获取、稳态重绘、进度到属性之通用映射 | 判其是否属「输出 `f64` 之解析」；是则回流 |

新原语不得预先实现。
未经验证之接口，宁可留白，不可臆造——`animator.rs` 中 `Animator` / `Animation` 至今为预留，即为明证。

判据：通用者回流，专用者先留调用方。
仅一处需要者为专用；第二处亦需要时，即为通用，当入 Sokuou。

---

## Ⅱ · 回流之法

于 Sokuou 仓内，一次回流之序：

1. 改正典（若法或律随之而变）。
2. 改原语（`*.rs`）。
3. 补测试——数值、语义、边界皆验；凡改数值，必附回归。
4. `cargo test` 与 `cargo clippy` 无新增告警。
5. 提交：Conventional Commits；正文中文，句句以句号终；一个功能块一次提交，可独立回滚者分开提交。

回流不得破之不变量：

- 零外部依赖，纯 Rust，无 `unsafe`，无平台 `cfg`。
- 输出仍为 `f64`；不退化为渲染器、时间线或全局服务。
- 帧率无关与解析解之约不得破。
- 破坏性变更须同步消费方——Ether 侧子模块指针由主仓调度者更新，Kanesumi 侧为 git 依赖。

若缺陷现于消费方仓，而一时不能在 Sokuou 内完成修复：
先在消费方留下记录——场景、证据、复现之法——补丁须带 TODO 与回流期限；
不得静默 fork，不得任其长存。

---

## Ⅲ · 调用者之义务

凡调用 Sokuou 者——人或 agent——既是使用者，也是建造者：

1. 先读正典 `docs/SOKUOU.md`，再动动画。
2. 缺方向时，向要求者问明方向；不得因无现成求解器与渲染管线而停工，亦不得弃 Sokuou 而他求。
3. 以所求之方向，用 Sokuou 原语构筑动画系统；宿主（帧循环、渲染、布局、输入）自备。
4. 遇缺陷、缺曲线、缺原语：按 §Ⅱ 回流。
5. 不得私藏曲线，不得另立长期演进之私有动画库。

---

## Ⅳ · 正典与代码

正典不得落后于原语。
凡语义有变，先或同时修正典；代码与正典冲突时，以正典为准——除非本次变更即含正典之修订。

回流之记录，存于本仓 git 历史，不另立账本。
