# Sokuou 即応エンジン 正典

> 动画不是播放，而是空间状态的连续解析。
> `state → progress → resolved spatial state → render`

---

## Ⅰ · 定位

### 总述

Sokuou 由二物构成：

- **原语** —— 本仓根目录之 `*.rs`。动画词汇之唯一真源。
- **文档库** —— `docs/`。本正典定概念与契约，调用指南述实践，回流指南承接使用所得；入口见 [README.md](README.md)。

Sokuou 不是渲染器。

其不绘制像素，不持窗口，不处理输入，不决定布局，亦不管理应用状态。

Sokuou 之输出，唯一 `f64`。
调用者将此值解为位置、透明度、缩放、旋转——或任何可由进度解析之量。

故：

采用 Sokuou 的过渡，以其原语作为共同动画词汇；具体应用自定交互与视觉风格。
使用中所得之通用经验、曲线与原语改进，宜带回公共文档与本仓（参 [BACKFLOW.md](BACKFLOW.md)）。
本文不要求调用者属于特定项目，亦不将本仓工作流施于所有消费方。

### 存在方式

Sokuou 以库嵌入：无守护进程，无全局单例，无注册中心。

```rust
struct DockPanel {
    slide: SpringAnim, // 本面板之滑入
}
```

每个组件自持其动画实例，构造时即定初始条件，析构即释放，无善后之务。

## Ⅱ · 何为 Sokuou 动画

### 非播放，乃解析

Sokuou 无时间线，无关键帧，无 clip，无 `play_animation()`。

```
state → progress → resolved spatial state → render
```

而非：

```
play_animation() → timeline → render
```

动画非「被播放」，乃系统状态被连续计算后之结果。
用户不应觉得「动画正在播放」，而应觉得「空间正在变化」。

### 连续

任意 progress 值，皆对应唯一确定之空间状态。

需要过渡的状态，不应有无意的 pop-in、骤生、骤灭或断点。
元素进退通常以 progress 由 0 至 1、由 1 至 0 解析之，退出完成后再卸载。
初始化、明确的即时切换及减少动态效果策略可以直接到位，由宿主决定。

### 可中断

任意时刻可改其目标。
中断时不得归零重演，而当承当前之值续行其路。
`SpringAnim` 兼承当前速度；`Progress` / `MetroAnim` 从当前值重启定时过渡，不承诺速度连续。

## Ⅲ · Progress

### 本质

```
归一化过渡的端点：progress = 0.0 → 起始态；progress = 1.0 → 目标态
```

progress 不是时间，不是帧数，不是「播放到百分之几」。

progress 是**当前空间状态值**。
`0.25` 不谓「已播四分之一」，而谓「系统此刻真实处于四分之一之空间状态」。

`[0,1]` 是常用端点约定，不是全部原语对输出的强制限制。
弹簧可过冲，也可直接驱动其他标量值域；`Progress` / `MetroAnim` 的起点与目标同样由调用者给定，部分 UWP 曲线亦可过冲。
位移需要弹性时保留原值；透明度等受限属性在解析时用 `map_range_clamped` 或相应约束。

### 时间之职

```
time     → 决定 progress 之变化速度
progress → 决定空间状态
```

时间可以影响速度、阻尼、惯性；
端点、布局等解析上下文给定时，过渡中的空间状态只由 progress 决定。

故任意时刻之渲染结果可写作 `render_state = resolve(progress)`。
`resolve` 须确定、连续、可停留于任意值。

### 一 progress，多属性

同一语义过渡之诸视觉属性，当由同一 progress 派生。

主运动（位移、缩放）以 `SpringAnim` 或 `Progress` 生成 progress；
次要属性（透明度、颜色）自同一 progress 以 `map_range`、`map_range_clamped` 或缓动函数派生。

不要为同一过渡之不同属性无故各立动画，以免空间失去一致。
同一元素的独立状态（如 hover 与按压）可分别驱动；有意的错位须能说明其交互语义。

### 主次之别

| 属性 | 原语 | 缓动 |
|---|---|---|
| 位移 / 缩放 / 面板滑入 / 页面切换 | `SpringAnim` | 内置物理 |
| 独立淡入淡出 / 颜色 / 固定时长过渡 | `Progress` | 默认 `EaseOutCubic`；颜色可用 `Linear` |
| UWP 规格已定之短时过渡 | `MetroAnim` | `UwpEasing` × `EasingMode` |

原则：主运动优先用弹簧；同一过渡之次要属性同源派生；独立定时过渡用时长驱动；凡 UWP 规格已定者，从其规格。
非交互淡入可不用弹簧（`Progress` + `EaseOutCubic`）；需循环时，由宿主定义重复或换向策略，缓动可选 `EaseInOutCubic`，日常交互不推荐。

## Ⅳ · 调用之法

### 循环契约

1. 于状态结构中持有动画实例——字段，非全局。
2. 事件处理器中于目标变化时 `set_target()`，并向宿主请求首帧；不要在渲染期反复重设目标。
3. 每更新步 `update(dt)` 一次，`dt` 为宿主单调时钟所得之有限、非负秒数。
4. 有动画未稳（`!is_steady()`）时，请求下一帧；本步刚到稳态亦须绘制最终值，此后不因该动画继续重绘。
5. 渲染期只读 `value()`，绝不修改动画状态。

```rust
use sokuou::{SpringAnim, map_range_clamped};

let mut slide = SpringAnim::new(0.5, 0.825, 0.0); // response, damping_ratio, initial
slide.set_target(1.0);                             // 任意时刻可中断
request_repaint();                                // 事件唤起首帧
slide.update(dt);                                 // 更新阶段；弹簧内部有时间保护策略
if !slide.is_steady() { request_repaint(); }       // 请求下一帧；本帧仍绘制最终值
let x = map_range_clamped(slide.value(), 0.0, 240.0); // 渲染期只读；此例有意限制位移过冲
```

签名之权威在源码 rustdoc（`cargo doc --open`）；正典定法与律，不逐条罗列签名。
初始化或即时到位须从各原语之 API：`SpringAnim::new(..., initial)` 定初值，`set_target()` 后 `snap()` 可直接到目标；`Progress` / `MetroAnim` 用 `jump_to()`。
完整宿主适配例与生命周期见 [INTEGRATION.md](INTEGRATION.md)。

### 时间策略与边界

`SpringAnim` 在 `dt > 0.25s` 时直接吸附，否则累计 `dt.min(0.05)`。
`Progress` / `MetroAnim` 则累计传入的 dt 至时长终点；调用者不可假设它们共享弹簧的停顿保护。
宿主负责提供有效时间输入；当前 API 不构成对任意负数、NaN 或无穷输入的有效行为保证。

弹簧使用解析解，在相同累计求解时间与初始条件下，轨迹不依赖采样帧率。
时间钳制、长停顿吸附与稳态阈值是额外策略，因此极低帧率或停顿下不承诺与真实墙钟时间完全相同的轨迹。

### 手势

手势结束，以手势速度为弹簧初速：`set_target_with_velocity(target, velocity)`。
速度须换算为动画值 / 秒，与目标及当前值处于同一单位。
物自有其动量，不因指离而骤停。

### 参数族

弹簧（`SpringAnim::new(response, damping_ratio, initial)`）起步建议，非规格保证或所有应用的统一标准。
`response` 为响应时间尺度，并非固定完成时长；最终应结合交互验证：

| 场景 | response | damping_ratio |
|---|---|---|
| 页面转场 | 0.40 | 0.80 |
| 通用交互 / 面板滑入 | 0.50 | 0.825 |
| 弹窗弹入 | 0.45 | 0.70 |
| 快速交互 / 图标反馈 | 0.30 | 0.60 |
| 慢速展示 / 通知 | 0.65 | 0.85 |

时长驱动（`Progress`）：非交互淡入 0.2s `EaseOutCubic`；淡出 0.15s `EaseInCubic`；
UWP 规格过渡默认 0.25s `Quadratic` / `EaseOut`。

调用方已有经验证的交互规格或预设者，从其预设；应用特有参数不因被某一项目采用而成为公共标准。

### 宿主之职

Sokuou 不提供帧循环、渲染管线、布局与输入。

凡构建动画系统者——人或 agent——须自备宿主：取 dt，驱动 `update`，读 progress，映射为视觉属性。
以本正典为法，按所求之方向构筑。

影响交互语义的方向不明时，当向要求者问明；一般实现细节可据默认实践推进并说明假设。
宿主机制由调用方补齐；缺少某框架适配不等于缺少动画原语。
凡此过程中所得之经验，应简述于调用方任务总结；值得共享者按 [BACKFLOW.md](BACKFLOW.md) 整理反馈。

### 禁止

| 禁止 | 缘由 |
|---|---|
| 以不可中断的播放流程替代状态驱动 | 无法随交互目标即时续行；约束的是语义，而非宿主方法的命名 |
| 渲染函数中修改动画状态 | 渲染只读 |
| 无意的 pop-in（骤现）或先卸载再淡出 | 违空间连续；正确初始化并保留退出态 |
| 同一过渡之属性无故各自驱动 | 违一致性 |
| 将通用问题长期仅作调用方特例而不整理经验 | 重复维护、难以复用；宜记录并促成上游改进 |
| 将 Sokuou 当作渲染器或时间线引擎 | 违定位 |

## Ⅴ · 设计不变量

| 不变量 | 含义 |
|---|---|
| 可中断 | 任意时刻可改目标、反向、接管、回弹，不锁定 |
| 连续 | 需要过渡的状态以 progress 解析；避免无意的骤现骤灭 |
| 进退有据 | 淡出、进入与卸载服从真实状态；是否交叉淡入由具体交互决定 |
| 进度有据 | progress 来自状态、时间或物理驱动；属性映射与缓动不冒充真实任务完成率 |
| 状态驱动 | 事件改变目标，更新推进，渲染只读 progress |
| 确定 | 任意 progress 值有唯一解析结果 |
| 采样无关 | 弹簧用解析解；相同求解时间与初始条件下轨迹一致，时间保护策略见 §Ⅳ |
| 空间真实 | 用户不应觉得「动画在播放」，而应觉得「空间在变化」 |
